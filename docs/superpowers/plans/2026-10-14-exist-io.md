# exist.io — Open-Source Origin-Compatible Forge Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `exist.io`, an open-source, self-hosted Git forge for people and coding agents. Its core product is usable without Cursor services; Origin API compatibility is a deliberate adapter that lets selected Origin clients work against exist.io.

**Product reference:** Cursor's current documentation describes Origin as its Git forge with standard Git clone/push/pull, GitHub mirroring, code browsing/search, pull requests, apps, and agent integrations ([Origin docs](https://cursor.com/docs/origin)). Cursor announced its acquisition by SpaceX on August 14, 2026 ([announcement](https://prod.cursor.com/blog/joining-spacex)); this is background only and does not change the product boundary.

**Architecture:** Go HTTP server, SQLite metadata store, Git object storage, and a self-hosted identity/auth layer. Expose compatibility routes under `/v1/origin/*`; keep internal identity, storage, merge, mirror, and delivery behavior owned by this project. Use the pinned Origin OpenAPI artifact as the wire-contract source. Generate local code from it only where that improves traceability; do not assume the original proto definitions or generator are available.

**Tech Stack:** Existing baseline is Go 1.26.0, `go-git/v6`, `modernc.org/sqlite`, and `oklog/ulid` (see `go.mod`). Keep this stack unless implementation evidence requires a change. `connectrpc` and `protoc-gen-openapi` are not current dependencies and are not prerequisites.

**Contract baseline:** The local Origin OpenAPI snapshot at `/tmp/opencode/origin-spec/openapi.yaml` contains 119 `operationId` entries and has SHA-256 `8e23b604a66d529f595be5949404092264b8513bd2e4713ffb346c499d88b74d`. The public docs entry point is [Cursor Origin API docs](https://cursor.com/docs/api/origin). The local CLI artifact is `/tmp/opencode/origin-bin/co` (SHA-256 `d653ba55831cb698cdce49167a85ffc5a7d7d839d633c8a62fa17b073be04011`); provider source is `/tmp/opencode/tfcursor/`. These `/tmp` paths are evidence inputs, not durable project dependencies. Task 0 records durable provenance and creates the checked-in operation inventory before further compatibility work.

**Product boundary:** Match client-visible routes, request/response fields, enums, auth metadata, and errors where evidence supports them. Design our own server behavior where Origin's server internals are unknown. Do not depend on Cursor's account API, API keys, signing keys, or admin endpoints at runtime.

Acceptance: a client can create a repository, clone it, commit and push, then clone/fetch the pushed commit; unauthorized reads/writes and nonexistent repositories receive correct protocol/HTTP failures; no Cursor-hosted Git endpoint is involved.

5. **Tasks 11 onward — Deliver REST groups in vertical slices.** For each operation inventory row, implement route + scope metadata + DTO/error behavior + persistence/engine behavior + request/response/negative tests. ### Definition of done

- A fresh self-hosted install starts without Cursor credentials, remote services, or manually seeded database state.
- Core forge path works end to end: create repo → clone/push/fetch over Git transport → create/update/merge PR → read resulting refs and checks.
- Every claimed Origin-compatible operation is listed in the checked-in inventory and has a contract test for success, auth denial, not-found, and validation behavior as applicable.
- Security boundaries are explicit: tenant isolation, repository permission checks on REST and Git transport, credential expiry/revocation, webhook key ownership, and secret redaction.
- MCP and CLI capabilities are derived from implemented operations; no stub tool is advertised as working.
- Docs distinguish observed wire facts from project-designed behavior and list unsupported Origin product features.

## Reverse-Engineering Summary (the target we are cloning)

### API surface (119 operations in the pinned snapshot)

Do not maintain a hand-counted thematic table as the operation source of truth. Task 0 creates a generated inventory from `operationId`, HTTP method, path, and `x-origin-scopes`; use that file for exact counts and coverage. The groups below describe implementation order, not exhaustive operation membership.

### Auth model
- **Three token types:** `app` (Ed25519 JWT), `installation` (`oit_…`, ≤15 min), `user` (OAuth user credential).
- **Token exchange:** raw `key_`/`crsr_` API key → `POST {endpoint}/auth/exchange_user_api_key` → `{accessToken, refreshToken}`.
- **Scopes (34 total):** 33 strings appear in `docs/reverse-engineering/scopes-34.txt`; `namespace:user_tokens:write` is the additional installation-only scope called out by the evidence notes. Derive and verify the final catalog from every operation extension in Task 0.
- **x-origin-scopes extension** on every operation: `tokenTypes`, `scopes`, `ambient`, `installationScopes`.
- **Observed upstream admin APIs:** Origin's Terraform/client flows use Cursor team/group lookup endpoints. exist.io must resolve principals from its own user/group directory and must not call these Cursor APIs at runtime.

### Key entities & enums
- **Repo:** `id` (`repo_…`), `name`, `fullName`, `owner{slug,id,type}`, `defaultBranch`, `cloneUrl`, `mirror{source,sourceId,status}`, `visibility`(internal|private), `allowMergeCommit`, `allowSquashMerge`, `deleteBranchOnMerge`.
- **Owner/Namespace:** `slug`, `id` (`ns_…`), `type`(user|team).
- **Grant:** `user{user_…}` | `group{grp_…}` | `teamGroup{members|admins}` + `permission`. Repo: `read|write|admin|custom`. Namespace: `read|contributor|write|admin|custom` (sent as `PERMISSION_READ` etc.).
- **Ruleset:** `enforcement`(active|evaluate|disabled), `kind`(merge_branch|push_branch|push_tag|push_repository), `rules[]` (ruleType + parameters), `bypassActors[]`.
- **PullRequest:** `id`(`pr_…`), `number`, `state`, `draft`, `merged`, `title`, `body`, `head`/`base` (PullRequestRef), `author`, `labels`, `mergeCommitSha`, `autoMerge` (PREVIEW).
- **CheckRun:** `id`(`cr_…`), `status`(queued|in_progress|completed|rerequested), `conclusion`(success|failure|neutral|cancelled|timed_out|action_required|stale|skipped).
- **Webhooks:** 35 event types. Signature: Ed25519 `v1ed` over `SHA256({webhook-id}.{webhook-timestamp}.{body})`. Verify against `/v1/origin/keys`.
- **MCP:** 33 tools in the current evidence notes, stateless streamable HTTP at `/mcp` and `/mcp/readonly`; independently inventory tool definitions before claiming parity.

### CLI command surface (Origin CLI, Bun-compiled artifact)
`origin app create|edit|list|view|webhook deliveries|ping|redeliver`, `origin pr list|view|checks|thread list`, `origin repo list|view|edit|mirror status|sync|transition|force-cutover|detach`. Config via `CURSOR_ORIGIN_ENDPOINT`, `CURSOR_API_KEY`, `CURSOR_AUTH_TOKEN`, `ORIGIN_REPO`, `ORIGIN_TIMEOUT_MS`. Headers: `x-cursor-client-type`, `x-cursor-client-version`, `x-cursor-team-id`.

## Global Constraints

- All compatibility API routes MUST be under `/v1/origin/` and match Origin's path shapes exactly (including `:action` verbs like `:syncMirror`, `:entries:replace`, `:grep`, `:batchGet`). Health and first-run bootstrap routes are exist.io product routes and must be documented separately.
- All IDs MUST use Origin prefixes: `app_`, `inst_`, `ns_`, `repo_`, `pr_`, `cr_`, `crg_`, `cra_`, `nsca_`, `nsip_`, `whd_`, `wha_`, `evt_`, `grp_`, `user_`, `stk_`, `oit_`.
- All enums MUST use Origin's exact wire values (e.g. `PERMISSION_READ`, `PERMISSION_CONTRIBUTOR`).
- Auth MUST enforce the exact per-operation `x-origin-scopes` metadata in the pinned contract. Local credential issuance and principal resolution are project-owned.
- Publish an OpenAPI 3.1 compatibility document derived from the pinned contract and implemented routes. Proto generation is optional and must not be assumed to reproduce Origin's generator.
- Every error response MUST use Origin's `Status` envelope: `{code, message, details}`.
- Test files MUST use Go's standard `testing` + `httptest`; no external test framework.
- No cgo. Pure Go (`go-git/v6`).
- Commit messages MUST follow `feat:` / `fix:` / `test:` / `chore:` conventional commits.
